# GitHub 阅读版与更新方式

仓库的文章原文保存在 `public/data/journal-entries.json`。`README.md` 和 `docs/2026/` 是生成的阅读版，不能只修改生成文件，否则下次同步会覆盖。

## 每次同步

```bash
npm run docs:github
npm run test:github-docs
npm run check:release
```

生成器负责首页最近更新、完整归档、文章导航、已知发布日期、原文入口与本地配图。没有记录的日期不补写。

## 排版与原文分开

- `scripts/generate-github-docs.mjs`：首页与文章外框。
- `scripts/journal-markdown-format.mjs`：正文的段落、标题、列表、引用和表格。
- `articleLayouts`：人工核对过的复杂文章结构；用原文中的完整句子定位，不靠容易失效的行号。

普通文章自动统一段落间距。中文编号小标题可以自动识别；阿拉伯数字章节仅对已核对的文章启用，避免把版本号、数据和提示词里的步骤误当成标题。简短日志不强行增加章节。

新导入的长教程，应对照原文在 `articleLayouts` 中补充标题层级、提示词范围、列表范围和表格维度，再检查生成后的阅读效果。定位句被修改或表格尺寸不匹配时，生成会报错，要求重新核对。

## 必须保留

- 原文的文字、标点、段落顺序，以及当时的判断和语气。
- 重复或跳号的原始编号，不让 Markdown 自动重新编号。
- 全部图片及原来的顺序。
- 完整文章目录与固定文件路径。

摘要仍留在网站数据中，GitHub 正文不再额外插入一遍，以免与文章开头重复。长文目录折叠显示；文章间导航沿用网站的期号排序，周报按周数乘七插入。

格式测试逐篇检查原文覆盖、配图顺序、目录链接、导航和生成文件一致性。它不能代替肉眼检查；调整规则后仍需预览一篇短日志、一篇长教程和一篇带提示词或表格的文章。
