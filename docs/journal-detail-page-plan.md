# 实录独立详情页方案（低风险版）

目标：在不破坏现有 `/journal` 列表与弹窗体验的前提下，新增可分享、可收录的独立详情页。

## 一、现状与问题

当前实录主要通过列表卡片 + Modal 展示，存在以下长期问题：

- 单篇内容无法稳定分享（缺少独立 URL）
- SEO 收录能力弱（搜索引擎不易理解单篇结构）
- 内容资产沉淀困难（后续做检索、推荐、统计会受限）

## 二、目标状态

新增路由结构：

- `/journal`：列表页（保留）
- `/journal/:slug`：详情页（新增）

兼容策略：

- 现有点击卡片行为可以保持弹窗（第一阶段）
- 逐步把“查看详情”入口切到独立页面

## 三、分阶段落地（建议）

### 阶段 1：只加路由，不替换主交互

- 新增详情页组件，按 `slug` 从 `journal-entries.json` 中查找条目
- 列表页保持现状，新增“复制链接/打开详情”按钮
- 若 `slug` 不存在，显示友好 404

风险最低，且能立即获得分享能力。

### 阶段 2：SEO 增强

- 为详情页输出专属 `title/description`
- 增加结构化数据（Article JSON-LD）
- 增加站点地图条目（包含每篇实录 URL）

### 阶段 3：交互统一

- 逐步从弹窗过渡到详情页（或双模式并存）
- 仅保留弹窗作为快速预览

## 四、数据要求

每篇实录建议新增字段：

- `slug`（字符串，唯一）
- `date`（推荐，便于排序和SEO）
- `seoTitle`（可选）
- `seoDescription`（可选）

## 五、验收标准

- 任意实录可通过固定 URL 访问
- 刷新详情页不会 404（服务器 SPA fallback 已配置）
- 从详情页可返回列表页
- 详情页在移动端阅读体验正常

## 六、回滚策略

若上线后异常：

- 保留原 `/journal` 弹窗路径不变
- 关闭详情入口按钮，仅保留列表页
- 数据字段新增不影响旧渲染，可快速回滚
